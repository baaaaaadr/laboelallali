# Page: / (Home Landing Page)

## Purpose
This is the main landing page of the Laboratoire El Allali PWA. It serves as the primary visual gate, detailing services, coordinates, active hours, practical instructions, and direct scheduling shortcuts.

## Directory & Files
- **Server Metadata Entry:** `src/app/[lang]/page.tsx`
- **Main Client Component:** `src/app/[lang]/HomeClient.tsx`
- **Type:** Hybrid (Server metadata + Client layout with optimized code-split subcomponents).

## Architecture & Sub-Components

### 1. Metadata Generation (`generateMetadata`)
- Defined in `src/app/[lang]/page.tsx` as a standard Next.js App Router metadata builder.
- Automatically serves translated titles, keywords, descriptions, and OpenGraph parameters for French and Arabic based on the route context.

### 2. High-Performance Client Shell (`HomeClient`)
- Renders the `HeroBanner` with an interactive "Opening Hours" widget above the fold.
- **`HeroPersonalPanel` (personalised, 4 states):** lives INSIDE the hero, not in the content container — see §2.0-bis. It replaced the `CheckupReminder` that used to be the first child here; do not mount that one on this page again, the same sentence would print twice.
- **`ServicesHub` (eager, priority CTA):** rendered right after the reminder in the content container, directly under the hero. Statically imported (NOT `next/dynamic`, NOT wrapped in `LazySection`) so the flagship Résultats call-to-action never flickers or waits on intersection. See §2.1. **It replaces the former `MainServices` section** (which only surfaced 3 services and duplicated analyses/glabo). `MainServices.tsx` still exists on disk but is now unused/orphaned.
- **Below-the-fold Lazy Loading:** To achieve near-instant initial loads and prevent blocking bundle downloads, the remaining sub-sections are imported using dynamic imports (`next/dynamic`) with client-side loading only (`ssr: false`):
  - `WhyChooseUs` (`@/components/features/home/WhyChooseUs`)
  - `LocationInfo` (`@/components/features/home/LocationInfo`)
  - `PracticalInfo` (`@/components/features/home/PracticalInfo`)
  - `ContactModal` (`@/components/ui/ContactModal`)
- **Viewport Observer (`LazySection`):** These lazy subcomponents are wrapped inside a helper observing the element's position via `react-intersection-observer` (`useInView`). Elements only hydrate and render when they are within 350px of the viewport, significantly optimizing DOM sizing and scroll performance. (`ServicesHub` is intentionally NOT wrapped — it is the priority section.)

### 2.0 Hero shortcuts (`HeroShortcuts`) — the five tiles inside the hero
- File: `src/components/features/home/HeroShortcuts.tsx`, rendered by `HeroBanner` **under the welcome paragraph and above the three historical fuchsia buttons** (Appeler / Whatsapp / Localisation). Added for demande n° 15 (août 2026); the lab dictated both the content and the order.
- **Order is the client's, do not "improve" it:** ① Faire mon bilan → `/${lang}/analyses?tab=bilans` (plain `/analyses` while `BILANS_ENABLED` is false — which actually matches the lab's own wording better: they asked for "faites votre PROPRE bilan", i.e. compose one from the catalogue) · ② Envoyer mon ordonnance → `/${lang}/rendez-vous` (the RDV form already accepts prescription uploads and leaves a traceable request; GLABO would have committed the patient to a home visit) · ③ Mes résultats → `/${lang}/resultats` · ④ WhatsApp Dr El Allali → `LAB_CONTACT.DR_WHATSAPP` · ⑤ Télécharger l'application.
- **`LAB_CONTACT.DR_WHATSAPP` (`0661291411`) is the doctor's own line**, added in `src/constants/contact.ts` for this tile. It is NOT `LAB_CONTACT.WHATSAPP` (the front desk, `0654079592`, used everywhere else) and NOT `COMPANIES` (`0661208635` — a deceptively similar number).
- **Styling: `.hero-tile` / `.hero-tile__icon` / `.hero-tile__label` / `.hero-tile__desc` in `src/styles/index.css`, NOT `.card`.** Five opaque light cards over the darkened hero photo, immediately above three fuchsia buttons, destroy the hero's readability — hence the frosted-glass treatment. The `color: … !important` is **mandatory**: four of the five tiles are `<a>` elements and the unlayered global `a { color: var(--text-accent) }` would otherwise win, leaving accent-coloured text on glass (the same trap documented for `.button-bordeaux-outline`). The rules live in `index.css` rather than `components/cards.css` because `index.css` is imported last and wins the cascade.
- **Tile ⑤ is `PWAInstallButton variant="tile"`** — a variant added for this grid, rendered as `<div role="button">` like `footer`/`icon` to bypass the global `button { background-color: transparent }` reset. **It renders `null` when the browser fires no `beforeinstallprompt`** (iOS Safari, or an already-installed app) and the grid falls back to four tiles. That is deliberate: `forceShow` would give iOS users a tile that does nothing. **Watch out when checking this — the button is ALWAYS visible under `npm run dev` (`NODE_ENV === 'development'`), so the four-tile case only appears in `npm run build && npm start`.**
- `HeroBanner` now takes a `lang` prop (passed by `HomeClient`) to build the hrefs.
- **The standalone `PWAInstallButton variant="button"` that used to sit in the hero's second row was removed** — two install CTAs 100 px apart. Installation is still reachable from the footer (`variant="footer"`) and the mobile menu (`variant="icon"`).
- **`pt-20 lg:pt-8` on the hero content block:** with the tiles added, the hero content exceeds `min-h-screen`, so `items-center` stops centring it and the `<h1>` rides up under the absolutely-positioned status badge. The padding is what keeps them apart — do not drop it without re-checking §3.
- **i18n:** `hero_shortcuts.*` in `public/locales/{fr,ar}/common.json`. Tile ⑤ reuses the existing `pwa.install_app_button` label plus `hero_shortcuts.install_desc`.
- **Known overlap, accepted:** "Mes résultats" appears here AND as the flagship banner of `ServicesHub` right below (§2.1). Judged a reinforcement rather than a duplicate. Note also that the fuchsia button labelled "Whatsapp" in the row below carries the i18n key `send_prescription` — a legacy naming inconsistency, and now a second "send your prescription" affordance pointing somewhere else (the lab's WhatsApp).
- **Unrelated wart left alone:** `HeroBanner` hardcodes `maps.app.goo.gl/7ZnXdXo9wiehq2tm7` while `LAB_COORDINATES.GOOGLE_MAPS_URL` holds a different short link. Both are opaque redirects and may point at different Google listings, so they were NOT merged blindly — open both and keep the verified business profile before unifying.

### 2.0-bis Hero personal panel (`HeroPersonalPanel`) — one block, four messages
- File: `src/components/features/home/HeroPersonalPanel.tsx`, rendered by `HeroBanner` between the welcome paragraph and `HeroShortcuts`. Props `{ lang }`, fully self-gated.
- **Why it is inside the hero.** The lab asked for the checkup reminder "on the home page, just under the hero" — where it already was. The hero is `min-h-screen` and, with the shortcut tiles, its content runs to ~1100px on a 390×844 phone: anything below it needs more than a full screen of scrolling. "Under the hero" is not "above the fold", which is the whole reason nobody ever saw it.

| State | Condition | Message → action |
|---|---|---|
| `guest` | `!user` | "Déjà venu au laboratoire ?" → `/login`, plus a quiet link to `/analyses` |
| *(nothing)* | `type === 'medecin' \| 'correspondant'` | slot collapses (`--collapsed`) |
| `noaccess` | `user && !userProfile?.requester_id` | "Activez l'accès à vos résultats" → `/resultats` |
| `reminder` | `status === 'ready'` and a parseable date | "Votre dernier bilan remonte à plus de X mois" → `/rendez-vous` |
| `generic` | everything else with a `requester_id` | "Pensez à votre prochain bilan" → `/rendez-vous` |

- **Three invariants, each of which cost a bug to learn:**
  1. **`loading` is the only trustworthy gate.** `AuthContext` calls `setUser()` **before** awaiting `fetchProfile()`, so there is a render where `user` exists and `userProfile` is still `null`. Gating `noaccess` on `user && !userProfile` flashes "activate your access" at a perfectly linked patient. `setLoading(false)` only runs after `setUserProfile`.
  2. **Never gate on `status === 'need_access'`.** `ResultsContext` starts its prefetch only when `requester_id` exists, so on the home page that status is **unreachable** — an unlinked account sits at `idle` forever.
  3. **Never call `computeResultsStats` outside `status === 'ready'`.** Its default `new Date()` is not deterministic between server and client; this code is safe only because it runs after hydration.
- **`generic` is the load-bearing state**, not a fallback: its sentence is true for any patient with no data at all, so it absorbs `idle`, `empty`, `error`, `unknown_id` and unparseable dates — there is never a permanent hole — and it has the same geometry as `reminder`, so the swap when results arrive changes one line inside a box of stable height.
- **The slot, the hint and the fade** — the page is statically prerendered, so the server HTML cannot know who is looking (reading a cookie would make the whole home page dynamic), and Firebase resolves `loading` 300 ms–1.5 s after first paint. Three tempting answers are all wrong: rendering nothing then popping in shoves the tiles and buttons down (a layout shift on the most visible element of the site); rendering the guest state server-side serves "create your account" to a regular patient for a full second; a plain empty reservation is a hole. So:
  1. SSR and the first client render both emit an empty `.hero-panel-slot` with its height reserved — identical output, no hydration mismatch, nothing to `suppressHydrationWarning`.
  2. On mount, a coarse `localStorage['laboElAllali_heroPanel']` hint (`guest | linked | noaccess`) paints the *likely* state immediately, with a 250 ms fade. No hint ⇒ guest: Firebase persistence lives in IndexedDB, so a returning patient always has one.
  3. When `loading` ends the real state takes over and the panel rewrites the hint. **`AuthContext` is untouched.**
  4. When `status === 'ready'` the generic title becomes the exact one.
- **The hint stores a category and nothing else** — never a month count, never a date, never an id. When someone's last bilan was taken is health metadata. A stale hint costs at most ~500 ms of a generic, always-true sentence.
- **Slot heights are measured, not guessed** (`min-height` 208 / 190 / 152 px). The tallest state is French `guest`, whose extra link wraps under the button; the three shorter states therefore leave some air below them — the price of a zero-shift hero, and over a photo it reads as spacing. Re-measure with the driver if any copy changes, and always round up.
- **Styling: `.hero-panel*` in `src/styles/index.css`, declared AFTER `.hero-tile`** — i.e. after `.hero-banner * { color: white !important }`, which is the whole mechanism: at equal specificity and equal `!important`, source order decides. The CTA is a white pill with `--color-fuchsia-bright` text and needs `!important` on `color`, because that global rule beats even an inline style (an `!important` sheet declaration wins over a plain inline one) — so the `ServicesHub` recipe of `style={{color}}` would give white-on-white here. `.button-bordeaux` was rejected: same hue as the hero overlay in light mode, remapped to pink in dark mode next to three fuchsia buttons. Known debt, shared with the `ServicesHub` CTA: `#F50057` on white is 4.18:1, under the AA threshold of 4.5:1.
- **Dev-only state override:** `?heroPanel=guest|noaccess|reminder|generic|none`, active only when `NODE_ENV === 'development'` (same trick as `PWAInstallButton`), so a Playwright driver can walk the four states without real accounts. It reads `window.location.search` and **not** `useSearchParams()` — that hook forces a `<Suspense>` boundary and would drop the home page out of static rendering.
- **i18n:** `hero_panel.*` (new) plus `resultats.access_title`, `resultats.checkup_*` reused verbatim. The month/year buckets live in `src/lib/results/checkupCopy.ts`, **shared with `/resultats`** so the two pages can never phrase the same bilan differently — changing a threshold there changes both.

### 2.1 Services Hub (`ServicesHub`) — flagship Résultats promotion
- File: `src/components/features/home/ServicesHub.tsx`. Section heading `services_hub.title` ("Nos services").

### 3. Real-Time Status Widget (`LabStatusWidget` + `useLabStatus`)
- `src/components/features/home/LabStatusWidget.tsx`, overlaid on the hero by `HomeClient` (absolute, top-centre mobile / top-right desktop). The pill shows **status AND countdown** (`Ouvert · ferme dans 3h06min`) and expands to the weekly-hours card on hover (desktop, `group-hover`) or click (mobile, `open` state).
- **Countdown in the pill (demande n° 13, août 2026).** It used to live only inside the popover, in a card that filled the top of the screen; the lab asked for it in the badge itself. Two consequences baked into the markup:
  - Status and countdown are **two separate flex children** joined by a `·` span, never one interpolated string — a `·` inside a string is mispositioned in RTL, a flex child follows the document direction.
  - **`aria-live="polite"` sits on the status span, NOT on the `<button>`.** With the countdown inside, a live region on the button makes a screen reader re-announce the whole badge every 60 s (`useNow` tick), forever. The status itself changes twice a day, so that is where the live region belongs.
  - The duplicate countdown pill was removed from the popover: the same value 40 px apart.
  - The wrapper in `HomeClient` carries `max-w-[calc(100vw-1.5rem)]`, and `HeroBanner`'s content block has `pt-20 lg:pt-8` so the absolutely-positioned badge never covers the `<h1>` (see §2.0 — the hero now overflows `min-h-screen`, so `items-center` no longer centres its content).
- **Hours live in ONE place: `src/constants/labHours.ts`** (`LAB_WEEKLY_HOURS`, indexed 0=dimanche…6=samedi). Lun–Ven 7h30–18h30, Sam 7h30–13h00, **dimanche fermé**. It is the only machine-readable schedule (badge, appointment slots, date pickers); the patient-facing text lives only in the `opening_hours_text` / `monday_to_friday` / `saturday_hours` i18n keys, which must agree with it (the old French-only `LAB_HOURS` constant has been removed). `getLabOpeningStatus(date)` is a pure function returning `{ isOpen, minutesUntilChange, nextChangeTime }`.
- **Timezone:** everything goes through `getLabClock()` → `Intl.DateTimeFormat` with `timeZone: 'Africa/Casablanca'`, never the device's or the server's local time (the SSR runtime is on UTC; Morocco is UTC+1, UTC+0 during Ramadan). The countdown is wall-clock arithmetic, so it may be off by 1 h across the two Ramadan clock changes — `isOpen` itself never is.
- **Three-state rendering — do NOT reintroduce `suppressHydrationWarning` here.** `useLabStatus` starts with `currentTime = null` and returns `isClient: false`, so the server render and the FIRST client render agree on a neutral grey `…` pill; the real status only appears after mount. This was a real production bug (fixed 2026-07-21): the page is statically prerendered (`generateStaticParams` → `.next/server/app/{fr,ar}.html`), so the server baked "Ouvert" at build time; `suppressHydrationWarning` on the badge told React to keep that server text, and since the client's render #1 and #2 both produced the same value React never patched the DOM — the stale "Ouvert" stayed until the status happened to flip. Any consumer must gate on `isClient` before showing `isOpen` (`ContactModal` hides its badge until then).
- **Ticking:** the clock itself lives in the shared `useNow()` hook (`src/hooks/useNow.ts`) — `null` until mount, first tick aligned on the next minute boundary, then every 60 s, plus a recompute on `visibilitychange`/`focus`/`pageshow` (timers are frozen in a backgrounded tab or installed PWA). The booking forms use the same hook, so the "never compute time during a render the server also performs" rule has a single implementation.
- Known gap: no public-holiday / exceptional-closure handling. `generateTimeSlots` (`src/utils/timeSlots.ts`, used by rendez-vous + glabo) now derives from the SAME `labHours.ts`, so booking and the badge can no longer disagree.

### 4. Device-Aware Contact CTA Actions
- Checks user-agent and window sizing on mount to separate mobile screens from desktop browsers.
- On mobile devices, telephone links directly trigger native calls. On desktop, standard click behaviors are intercepted to open the overlay `ContactModal` instead, avoiding dead links.

### 5. PWA manifest — link handling (`public/manifest.json`)
Not strictly a page concern, but this is where the home page is entered from, so it is recorded here.
- **`"handle_links": "preferred"` + `"launch_handler": { "client_mode": "navigate-existing" }`** were added for demande n° 14 ("when the app is installed, a Google link should open the app, not the browser"). `navigate-existing` reuses an already-open PWA window instead of spawning a second one.
- **There is NO `public/.well-known/assetlinks.json`, and there should not be.** Digital Asset Links proves that an APK signed by *our* key may capture the domain's links — that is for a Play Store TWA or a native app. Here the install goes through Chrome, which mints a **WebAPK signed by Google's own server** and performs the verification itself from the manifest. A hand-written assetlinks file with a fingerprint we do not own would do nothing.
- **If a TWA ever does appear**, two traps: `firebase.json` → `hosting.ignore` contains `"**/.*"`, which silently excludes any dot-directory (so `public/.well-known/` would never deploy); the robust workaround is a route handler at `src/app/.well-known/assetlinks.json/route.ts`. The middleware `matcher` already excludes paths with a file extension, so no locale prefix is added.
- **NEVER change `id` (`/?utm_source=manifest_id`) or narrow `scope`.** Chrome treats a changed id as a *different application*: every existing installation is orphaned and patients must reinstall.
- **Honest scope, for when the lab asks why it still opens in a browser:** real effect on Chrome Android, **none at all on iOS** (Apple does not allow link capture for a web app), and **no manifest can intercept a link opened from inside WhatsApp or Facebook** — those use their own embedded browser. The Android setting *Applications → LaboElAllali → Ouvrir par défaut* also has to be on, and is often the actual cause.

## Notes for AI
- **Performance Constraints:** When adding landing page sections, always use `LazySection` wrappers and dynamic imports with `ssr: false` to preserve the premium performance grade.
- **Scroll Animations:** An event listener automatically toggles `.visible` classes on `.fade-in-section` items as the patient scrolls down the page.
- **The hero is now height-constrained.** Between the status badge (absolute), the five shortcut tiles and the three buttons, the hero overflows `min-h-screen` on a phone. Anything added there must be re-checked at 320 px against §2.0 and §3.
