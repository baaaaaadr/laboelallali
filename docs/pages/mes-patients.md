# Page: /mes-patients

## Purpose
The **prescribing doctor's space** (23/09/2026, quote line 62 « Accès médecin — Mes patients »). A doctor who has an account in the app sees, separately from his own results and his relatives' (which stay on `/resultats`, untouched):
1. the list of **his patients** — the people whose lab reports **he prescribed**, and only those — with a search;
2. for one patient, **his reports**, newest first: the most recent PDF is loaded on opening, older ones on demand; view / download / share, exactly like a patient does.

**The rule « only the reports he prescribed » is enforced by the lab server**, not by the app: a dossier prescribed by another doctor answers 404, even for the same patient (verified on the real server on 23/09/2026 with a real prescriber code). The app only ever asks with the doctor's code.

The header menu is `src/components/layout/ResultsNavMenu.tsx`.

## Who sees what — the page's gate (`page.tsx`)
| Situation | Screen |
|---|---|
| not signed in | redirect to `/{lang}/login?redirect=/{lang}/mes-patients` — the login page shows a doctor hint and does NOT file the new account in the patient onboarding queue (§9) |
| no doctor access (`readPractitioner(userProfile) === null`) | **`PractitionerAccessRequest`** (§9): the form « Demander mon accès médecin », or where his request stands — pending (with **« Vérifier à nouveau »**: `refreshProfile()`, the profile is read ONCE per session, so an access the lab just gave would not show otherwise), refused (→ « Faire une nouvelle demande »). Lab phone + WhatsApp in every state |
| doctor code equal to one of the account's PATIENT ids | « Accès médecin à corriger » — **no call at all** (the server resolves the patient side first; the doctor would see his own results labelled « Mes patients »). The admin refuses this on write; this is the belt to that brace |
| doctor access, but the confidentiality engagement not accepted (`!hasEngagement(userProfile)`) | **`PractitionerEngagementGate`** (§10): the engagement, once — **no call to the results server before he accepts** |
| otherwise | `<PractitionerWorkspace key={uid + ':' + code} practitioner={…} />` |

## Context & Key Components

### 1. The doctor access (`users/{uid}.practitioner`)
`{ requester_id: "MOUSTZOU", type: "medecin" | "correspondant", label: "Dr …", linkedAt, linkedBy, lastUsedAt? }`, written ONLY by `adminSetPractitioner` (admin level), **locked in `firestore.rules`** (both lists). Read through `readPractitioner()` — same validity test as the server (`practitionerIdentity`).

**⚠ Invariant: the doctor access is NEVER one of the patient identities.** `resolveIdentities()` / `primaryIdentity()` ignore it, so it is never the home page's « VOTRE dernier bilan », never a tab of the family selector, never on the barcode, never prefetched at login. Server side, `resolveIdentity()` returns it only on an explicit, exact selector, and the patient side wins a collision. Tested by `functions/scripts/test-identities.js` (sections 9–15), `scripts/test-practitioner.js` (D) and `scripts/test-practitioner-ui.js` (M7).

### 2. Data — one call for the list, one per PDF
- `useResultsFor(practitioner.requester_id)` — the shared results context (`src/contexts/ResultsContext.tsx`): bucket `${uid}::${code}`, PDFs `${code}::${dossierId}`, memory only, reset on logout / account switch. **Never `useResultsFor(null)`** — that is the account's PRIMARY identity (the doctor's own results).
- **List:** `fetchResults({ include_pdf: "none", requester_id: CODE })`. The server FORCES `none` for a practitioner whatever the client sends (a 50-dossier roster with PDFs would blow the 20 s transport timeout and raise a false outage alert). Measured: 0.25 s.
- **No PDF is auto-loaded after the list** for a practitioner identity (`autoPdfIds` in `ResultsContext` = patient-side identities only): the newest dossier of a roster is some patient the doctor did not ask to open.
- **Opening a patient** loads the PDF of **that patient's** most recent report, once (`PatientDetail`); older PDFs on « Voir » / « Télécharger ». One PDF ≈ 2.5 s, ~260 KB.
- **Telemetry** (server): `usageDaily.practitionerConsultations` + `practitioner.lastUsedAt` (6 h throttle, conditional write) — never the patient counters, never the relance list. **Per doctor (24/09/2026)**: `practitionerUsage/{uid}` (`functions/src/admin/practitionerUsage.ts`, written by `fetchResults`, server only) — `days` (days with a visit = a list load, UTC days, counted once per day in a transaction), `reports` (reports opened = a `dossier_id` fetch for which the lab REALLY returned a PDF), `firstAt`/`lastAt`/`lastReportAt`, and `months: {"YYYY-MM": {days, reports}}`. **Counts and dates only — never which patient, never which dossier.** Kept out of `practitioner` on purpose (that map is the access grant, deleted on withdrawal, and what this page reads). It feeds the admin « Médecins » tab and the dashboard's « Les médecins » (`docs/pages/admin.md`); the doctor is told in his engagement (« le laboratoire enregistre la date et le nombre de mes consultations (jamais lesquelles) »).

### 3. Grouping and search (`src/lib/practitioner/patients.ts`)
The lab returns **no patient identifier** (`patient_id` is ignored by the server) — only `patient_nom` / `patient_prenom`. `patientKey()` = accents off, capitals, punctuation → space, spaces collapsed; **nameless dossiers are never merged** (one line each, keyed on the dossier number). `groupByPatient()` sorts patients by most recent report, ties by name (stable between refreshes). `matchesQuery()`: every typed word must appear in the name (accent/case/order-insensitive) or START a dossier number. `displayName()`: « EL ALLALI Hassan ».

**⚠ Known limit, stated on screen (`mes_patients.homonym_note`):** two different patients with exactly the same family name and first name appear as one line; each report keeps its date and dossier number. A stable patient id from the lab (asked to Si Brahim) would remove it. The server's twin `patientKey` (admin « Vérifier » counts, `functions/src/admin/adminPractitioner.ts`) must stay identical, **nameless rule included** (it takes the dossier number as a third argument; until 23/09/2026 it merged every nameless dossier into one patient, so « Vérifier » undercounted) — checked by `scripts/test-practitioner.js` (E) and `functions/scripts/test-practitioner-admin.js`.

**The 50 cap.** The lab server returns at most 50 dossiers, **newest first, and truncation keeps the most recent** (verified 23/09/2026 with `max_results: 1` on four identities). At 50, `mes_patients.capped` says only the 50 most recent are shown.

### 4. States (`PractitionerWorkspace`)
`idle`/`loading` → loader · `need_access` or `permission-denied` → « accès retiré ou modifié » + contacts · `unknown_id` (lab 404: no dossier sent yet since the doctor's activation in Qalam) → « pas encore actif côté laboratoire » + contacts · `error` → rate-limited / confirmed outage (`useOutageStatus`, + `OutageOptIn`) / generic, with « Réessayer » · `empty` → « Aucun bilan pour le moment » · `ready` → search + summary (« N patients · M bilans », plural forms fr + ar) + list/detail.

### 5. Layout and the phone back button
- Large screens (`lg`): list (22 rem) and detail side by side. Phones: the detail **replaces** the list (`hidden lg:block` both ways).
- **Phone back button:** opening a patient on a phone (`matchMedia('(min-width: 1024px)')` false) pushes ONE history entry `{ mpDetail: 1 }`, same URL; `popstate` closes the detail and restores the list's scroll; the in-page « ← Mes patients » calls `history.back()`. Next.js patches `pushState` and keeps its own router state in the entry, so this is not a navigation. **Nothing identifying goes into the history state, the URL, the page title or a file name** (`resultat-<dossier>.pdf`).

### 6. PDF actions (`usePractitionerPdfActions`)
Same mechanics as `/resultats` (base64 stays in the context, the viewer keeps only the dossier id and closes by itself on an account switch). Differences: **neutral share texts** (`mes_patients.share_*`, never « Mon résultat »), viewer title « NOM Prénom — dossier N » (on screen only). `PdfViewerModal` got optional `title` / `shareTitle` / `shareText` / `fileName` props for this.

Every other account sees exactly what it saw before.
- **Desktop header — a two-item menu** (`src/components/layout/ResultsNavMenu.tsx`, mounted by `Header.tsx` instead of the plain featured link). The trigger keeps the featured look (fuchsia outline; the document icon from 1280 px only) plus a chevron, is marked « vous êtes ici » on either page, and opens a popover with the two entries and a one-line description each (`mes_patients.menu_mine_desc` / `menu_patients_desc`). Closes on Escape, outside click, scroll, resize and navigation; ArrowUp/ArrowDown move between the entries; opened from the keyboard, focus goes to the first entry.
  - **No extra top-level link, and « Médecins » stays**: the bar is full — measured 23/09/2026 on the production build, an 8th link overflows by 38 px at 1024 px in French (`docs/pages/resultats.md` §Notes). **Measured 24/09/2026** (production build, French, logged in): a doctor keeps **71 px** of margin at 1024 px (a patient: 69 px); a team member who is also a doctor overflows by **4 px** — the team's 8-link bar was already 6 px over before this menu. That needs the document icon hidden below 1280 px (`hidden xl:inline-block`): with both icon and chevron, the team+doctor case overflowed by 28 px. Staff accounts get the same menu.
  - ⚠ **The popover is portalled to `<body>`** with `position: fixed`: the desktop `<nav>` is `overflow-x-auto` (its overflow valve) and would clip it. The portal root carries `dir`/`lang` itself — it lives outside the `[lang]` wrapper.
  - ⚠ **The trigger is an `<a href="/{lang}/resultats" role="button">`**, not a `<button>`: the header's link rules are written for `<a>`, the global button reset would fight them, and a middle-click still opens the results page.

First element of `/resultats`, of the workspace, and of the collision screen of `/mes-patients`. ### 9. Asking for the access — the invitation link (owner's decision, 24/09/2026)
**The two onboarding cases.** (a) The lab already has the doctor's app account → an admin gives him his code directly (Patients tab, « Accès médecin » card, `docs/pages/admin.md`); he gets the e-mail « Votre accès médecin est actif ». No request. (b) He has no account yet → the lab sends him **the invitation link**, usually over WhatsApp (the lab has his phone, rarely his e-mail): card « Inviter un médecin », admin Demandes tab.
- **The link IS this page** (`/{lang}/mes-patients`, `src/lib/practitioner/invitation.ts`): before activation it shows the request form, after activation his patients — so the WhatsApp message is also his bookmark.
- **Not signed in** → `/login?redirect=/{lang}/mes-patients`. The login page then shows « Espace médecin : connectez-vous — ou créez votre compte… » (`mes_patients.login_hint`, `data-testid="login-doctor-hint"`) and **skips `autoRequestResultsAccess()`** for this target (`isDoctorSpacePath`): a doctor is not a patient asking for results — otherwise the front desk would call him to offer him his own results. See `docs/pages/login.md`.
- **The form** (`src/components/features/practitioner/PractitionerAccessRequest.tsx`, `data-testid="mp-request-form"`): his name **as printed on his prescriptions** (what the lab looks up in Qalam — prefilled « Dr » + his account name), specialty and city/practice (optional), then **his confidentiality engagement** (`EngagementTerms`, §10) and ONE required tick « Je suis médecin et j'accepte cet engagement » (`mp-request-attest`). The payload carries `engagement: PRACTITIONER_ENGAGEMENT_VERSION`; the server records it on his account, so the lab's activation does not ask him again. The locked button always says why. States from `myPractitionerRequest`: none → form · `pending` → « Votre demande est bien arrivée » (date, e-mail promised) + « Vérifier à nouveau » · `rejected` → message + « Faire une nouvelle demande » · `fulfilled` → re-reads the profile once (the workspace then opens by itself). « Vous êtes patient ? Voir mes résultats » links to `/resultats`.
- **Works for a doctor who never had a test at the lab**: nothing needs a patient dossier.
- **Asking grants NOTHING** (`requestPractitionerAccess`): anyone can claim to be a doctor in an app, and only the lab knows his Qalam code. The request lands in the admin Demandes tab (« Demandes d'accès médecin ») and the staff get an e-mail; the admin's « Ouvrir sa fiche et activer » selects his account with the card prefilled; activation (`adminSetPractitioner`) closes the request.
- Server: `functions/src/admin/practitionerRequests.ts` — `requestPractitionerAccess` (auth; one pending request per account, a second tap sends nothing; re-asking after a refusal starts clean), `myPractitionerRequest` (auth), `adminListPractitionerRequests` (≥staff), `adminRejectPractitionerRequest` (≥admin, nothing sent to the doctor — the lab calls him). Collection `practitionerAccessRequests/{uid}`, server only (default deny). Input validation `parsePractitionerRequest` (pure, `functions/scripts/test-practitioner-admin.js`).

### 10. The confidentiality engagement (owner's request, 24/09/2026)
« Je déclare ne pas partager avec autrui… il coche et puis fait sa demande. » Every doctor accepts, in the app, a short engagement — it replaces the paper engagement the lab procedure used to describe.
- **The text** — `src/components/features/practitioner/EngagementTerms.tsx` (`data-testid="mp-engagement-terms"`, keys `mes_patients.engagement_*`): results only for his patients' care; nobody else on his account; medical secrecy; tell the lab if his phone is lost or stolen, or if he stops practising; plus an acknowledgement (he sees only what he prescribed, the lab records the date and number of his consultations — never which —, the access can be withdrawn). **Shown open, not folded**: four short lines, and a commitment should be read before it is ticked.
- **Two moments, one record.** (a) The request form (§9): the single tick « Je suis médecin et j'accepte cet engagement ». (b) A doctor the lab activated DIRECTLY never saw that form: **`PractitionerEngagementGate`** (`data-testid="mp-engagement-gate"`) shows the same text once, before his first roster — « Une dernière étape avant vos patients », a tick « J'accepte cet engagement », « Accepter et ouvrir mes patients » (locked, and saying why, until ticked). It is rendered INSTEAD of the workspace: **no call to the results server before he accepts**. Accepting calls `acceptPractitionerEngagement({version})`, then `refreshProfile()` (the profile is read once per session); the workspace then opens by itself. A failed call keeps him on the gate with a message.
- **Where it is recorded:** `users/{uid}.practitionerEngagement = {version, acceptedAt, via: "request" | "visit"}` — on the ACCOUNT, not inside `practitioner`: withdrawing then giving back an access does not ask the same person again, and the record (the lab's proof) survives a withdrawal. Written only server-side (`requestPractitionerAccess`, `acceptPractitionerEngagement` — `functions/src/admin/practitionerEngagement.ts`), never overwritten once accepted, **locked in `firestore.rules`** (both lists: a client could otherwise forge the date, or skip the text by writing it).
- **A commitment, not a lock.** Access control stays the lab's activation plus the `practitioner` lock; `fetchResults` does not check the engagement — a stale page must never turn a formality into « accès retiré ».
- **Versioning:** `PRACTITIONER_ENGAGEMENT_VERSION` exists twice — `functions/src/admin/practitionerEngagement.ts` and `src/lib/practitioner/engagement.ts` (`hasEngagement`). Bump BOTH when the text changes materially: every doctor meets the gate again. `scripts/test-practitioner.js` (J) checks the two versions and verdicts match. A request sent by a page older than the text still goes through, without recording the engagement (asked at his first visit instead); `acceptPractitionerEngagement` refuses another version (« Rechargez la page »).
- **The admin sees it:** the request card (« Engagement de confidentialité accepté »), the « Accès médecin » card and the « Médecins » tab (accepted on…, or « il lui sera demandé à sa prochaine visite ») — `docs/pages/admin.md`.
